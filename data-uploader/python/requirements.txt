# Star Citizen Companion - Data Uploader · Python sidecar
# Pinned for reproducible builds.
#
# We use scdatatools ONLY as a P4K reader (zip central-directory + AES + zstd).
# The live SC 4.x DataCore is DataForge v8, which scdatatools 1.0.4's forge
# parser cannot read (the v8 record grew from 32 to 36 bytes, desyncing every
# later section). We therefore parse Data/Game2.dcb with our own pure-Python
# reader (sc_extract/dataforge.py) and rely on scdatatools only for opening the
# archive. Opening the live P4K additionally requires the runtime patch in
# sc_extract/p4k_compat.py (imported before constructing P4KFile).

scdatatools==1.0.4

# scdatatools imports these at module load even on the leaf p4k/forge path, so
# they must be installed for `from scdatatools.p4k import P4KFile` to succeed.
#
# ⚠ TRANSITIVE deps below: their versions are dictated by scdatatools 1.0.4's own
# metadata (scdatatools.egg-info/requires.txt), NOT free to pick. #200 blanket-
# pinned them to latest, violating scdatatools's `~=` ranges → `pip install -r
# requirements.txt` became unsolvable and every data-uploader-v* tag build failed
# at fetch-embedded-python (the CI test jobs never install requirements.txt, so
# it stayed invisible). Keep each within scdatatools 1.0.4's range; to lift any,
# bump scdatatools. Embedded Python is 3.10.x. See
# .claude/deep-knowledge/data-uploader-python.md.
