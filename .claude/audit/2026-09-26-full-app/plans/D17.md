## Schritte

Jeder Schritt ist ein Commit. Nach jedem Schritt: `npm run typecheck` und `npm test -- --include='src/app/codex/codex-detail*.spec.ts' --include='src/app/codex/detail/**/*.spec.ts' --include='src/app/codex/holo/**/*.spec.ts'`. Nach den Schritten 2–5 zusätzlich `npm run build` (Budget).

**Styles wandern mit.** View-Encapsulation bedeutet: Regeln im Style-Block von `codex-detail` greifen nicht mehr auf Elemente, die jetzt im Template einer Teilkomponente stehen. Das gilt auch für Nachfahren-Selektoren wie `.toolrow .picker`. Pro Teilkomponente deshalb:
- mit `grep -n "<klasse>" src/app/codex/codex-detail.component.ts` **alle** Regeln finden, die ihre Klassen treffen, auch zusammengesetzte;
- sie in die Teilkomponente verschieben;
- nur dort doppelt lassen, wo der Parent die Klasse weiter selbst benutzt (z. B. `.compat-list`, `.chip`, `.hint`, `.muted` für „Used in“/„Where to buy“).
- Kontextabhängige Regeln (`.toolrow .picker …`) werden in der Teilkomponente zu `:host(.in-toolrow) …`; der Parent setzt die Klasse am Host-Tag.
- Host der Teilkomponenten, die in einer Flex-Zeile sitzen: `:host { display: contents; }`. So bleibt das Layout exakt wie heute, der Host erzeugt keine eigene Box.
