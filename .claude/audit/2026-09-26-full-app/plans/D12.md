## Ziel und Definition of Done

- **Worker, Range:**
  - `Range: bytes=0-99` → `206`, `content-range: bytes 0-99/<size>`, `content-length: 100`.
  - `bytes=-50` → `206` mit echten Zahlen.
  - `bytes=<start ≥ size>-` → `416`, `content-range: bytes */<size>`, CORS-Header.
  - Ungültige oder mehrfache Bereiche (`bytes=5-2`, `bytes=0-1,4-5`, `items=0-3`) → `200` mit dem ganzen Objekt (RFC 9110 erlaubt, den Header zu ignorieren).
  - Jede `200`/`206`/`HEAD`-Antwort trägt `accept-ranges: bytes`.
- **Worker, Supabase-Fallback:**
  - `fetch` wirft oder die Header kommen nicht binnen 10 s → `502` mit CORS und `cache-control: no-store`.
  - Upstream `429` oder `5xx` → ebenfalls `502` mit CORS und `no-store`.
  - Upstream `400`/`403`/`404`/`410` → `404`.
  - Der `range`-Header wird weitergereicht, `206`/`416` kommen samt `content-range` durch.
  - Ein durchgereichtes `304` trägt das `etag`.
- **Worker-Tests** (`node --test`) decken ab: 206 (drei Formen), 416, ignorierte Bereiche, OPTIONS, Fallback bei Wurf/503/429/404/304/206.

### Schritt 1 – Worker: Range selbst auswerten (206/416, `accept-ranges`) mit Tests

**Dateien:** `cloudflare/assets-worker/src/index.js`, `cloudflare/assets-worker/test/index.test.mjs`.

**Änderung in `index.js`:**

- Neue, exportierte reine Funktion (neben `keyFor`, gleicher JSDoc-Stil):

  ```js
  /**
   * One `bytes=` range against an object of `size` bytes (RFC 9110 §14).
   * null            → serve the whole object (no header, other unit, several
   *                   ranges, syntax error — a server may ignore Range);
   * 'unsatisfiable' → answer 416;
   * otherwise the exact slice to read.
   */
  export function parseRange(header, size) {
    if (!header) return null;
    const m = /^bytes=(\d*)-(\d*)$/.exec(header.trim());
    if (!m || (m[1] === '' && m[2] === '')) return null;
    if (m[1] === '') {
      // suffix form: the last n bytes
      const n = Number(m[2]);
      if (n === 0 || size === 0) return 'unsatisfiable';
      const length = Math.min(n, size);
      return { offset: size - length, length };
    }
    const start = Number(m[1]);
    if (m[2] !== '' && Number(m[2]) < start) return null; // invalid range → ignore the header
    if (start >= size) return 'unsatisfiable';
    const end = m[2] === '' ? size - 1 : Math.min(Number(m[2]), size - 1);
    return { offset: start, length: end - start + 1 };
  }
  ```

  Die Reihenfolge der Prüfungen ist Absicht: Bei einem leeren Objekt (`size = 0`) ergäbe `bytes=0-` sonst `end = -1 < start` und würde als „ungültig“ mit 200 beantwortet statt mit 416.

- `baseHeaders(key)` bekommt `'accept-ranges': 'bytes'`. `CORS['Access-Control-Expose-Headers']` wird zu `'etag, content-length, content-range, accept-ranges'`.
- Neue Hilfsfunktion `unsatisfiable(size)`: `416` mit `{ ...CORS, 'content-type': 'text/plain', 'content-range': \`bytes */${size}\` }`.
- In `fetch()` einen eigenen Zweig für **GET mit `range`-Header** vor den heutigen `get`-Aufruf setzen:
  1. `const meta = await env.ASSETS.head(key);` Kein Objekt → `return fromSupabase(env, key, request);`.
  2. `const range = parseRange(request.headers.get('range'), meta.size);`
  3. Bei `'unsatisfiable'` → `return unsatisfiable(meta.size);`.
  4. Bei einem Objekt → `env.ASSETS.get(key, { onlyIf: request.headers, range })` mit dem **expliziten** `{ offset, length }`.
     - Ergebnis `null` (inzwischen gelöscht) → `fromSupabase`.
     - Ohne `body` → `304` wie heute.
     - Sonst `206` mit `content-range: bytes ${offset}-${offset + length - 1}/${meta.size}` und `content-length: length`, beide aus **unseren** Zahlen.
     - Die übrigen Header genau wie im normalen 200-Pfad bauen: `baseHeaders(key)`, `object.writeHttpMetadata(headers)`, danach `content-type` aus dem Key, `cache-control` und `etag: object.httpEtag`. Am einfachsten diesen Block in eine kleine Hilfsfunktion `objectHeaders(key, object)` ziehen und in beiden Pfaden nutzen.
  5. Bei `null` (Header ignoriert) → normal weiter.

  Der eine zusätzliche `head()` fällt nur bei Range-Anfragen an. Die sind selten, Browser holen `.glb`/`.webp` ohne Range. Die Class-B-Kosten sind vernachlässigbar, das Free-Plan-Limit zählt Requests, nicht Subrequests. Einen Satz dazu als Kommentar an den Zweig schreiben.
- Den normalen `get` auf `env.ASSETS.get(key, { onlyIf: request.headers })` reduzieren. **`range: request.headers` entfernen**, sonst wendet R2 einen Bereich an, den wir bewusst ignorieren.
- Den alten Block `if (object.range && request.headers.has('range')) { … }` (~Z. 115–122) löschen. Er liest `'suffix' in r`: R2 liefert den Schlüssel mit Wert `undefined`, daher `NaN`.

**Änderung in `test/index.test.mjs`:**

- `fakeBucket(objects)` wie R2:
  - `get(key, opts)` wirft `new Error('fake R2: range must be explicit')`, wenn `opts.range instanceof Headers`.
  - Bei `{ offset, length }` bzw. `{ suffix }` schneidet sie die Bytes und setzt am Rückgabeobjekt `range: { offset, length, suffix: undefined }`, so wie R2 den Schlüssel liefert.
  - `head()` bleibt.
- Testobjekt mit 10 Bytes (`'0123456789'`), neue Fälle in `describe('fetch')`:
  - `Range: bytes=0-3` → `206`, `content-range: bytes 0-3/10`, `content-length: 4`, Body `'0123'`.
  - `bytes=7-` → `206`, `bytes 7-9/10`, Body `'789'`.
  - `bytes=-2` → `206`, `bytes 8-9/10`.
  - `bytes=-20` → `206`, `bytes 0-9/10`.
  - `bytes=0-99` → `206`, `bytes 0-9/10`.
  - `bytes=99-` → `416`, `content-range: bytes */10`, `access-control-allow-origin: *`.
  - `bytes=5-2`, `bytes=0-1,4-5`, `items=0-3` → `200`, ganzer Body.
  - `200` und `HEAD` tragen `accept-ranges: bytes`.
  - `OPTIONS` → `204`, `access-control-allow-origin: *`, `access-control-allow-methods` enthält `GET`.
