## Schritte

### Schritt 1 — Hook erkennt seinen Aufruf plattformunabhängig (NEU-1)

Dateien:
- `.claude/hooks/pre.ask.unattended.mjs`
- `.claude/hooks/pre.ask.unattended.test.mjs`

Änderung:
- Im Hook die Imports erweitern:
  - Zeile 19 `import { join } from 'node:path';` wird zu `import { join, resolve } from 'node:path';`.
  - Neu: `import { pathToFileURL } from 'node:url';`.
- Die `isMain`-Zeile (heute Zeile 62, nach dem zusätzlichen Import Zeile 63) ersetzen durch das Muster aus `scripts/routine-gate.mjs:562`:
  ```js
  const isMain = process.argv[1] && import.meta.url === pathToFileURL(resolve(process.argv[1])).href;
  ```
  Warum: ``new URL(`file:///${argv1}`)`` ergibt auf POSIX-Pfaden (`/home/…`) `file:////home/…` und ist damit nie gleich `import.meta.url`. Der CLI-Zweig lief außerhalb von Windows also nie.
  Gegenprobe vom 2026-09-28: Dieselbe Änderung an einer Kopie in einem Scratch-Verzeichnis ergab `# pass 3 / # fail 0`.
- Nur falls ein Symlink-Pfad (z. B. macOS `/tmp` → `/private/tmp` oder ein verlinkter Checkout) doch abweicht: `realpathSync(process.argv[1])` aus `node:fs` statt `resolve(…)`, in `try/catch`, sonst `false`. Standardmäßig nicht nötig.
- Im Test Zeile 41 robuster machen, damit ein Checkout-Pfad mit Leerzeichen nicht als `%20` beim Spawn landet:
  `const script = fileURLToPath(new URL('./pre.ask.unattended.mjs', import.meta.url));` mit `import { fileURLToPath } from 'node:url';`. Das ersetzt `.pathname.replace(/^\/([A-Za-z]:)/, '$1')`.
- Den Kopfkommentar des Hooks (Zeilen 2–17) um einen Satz ergänzen: Der CLI-Zweig läuft auf allen Plattformen. Geplante Sessions erkennt er an den Desktop-Records unter `%APPDATA%\Claude\claude-code-sessions` (Windows, dort läuft die Routine). Ohne Record ist der Hook ein No-op mit Exit 0.

Prüfen:
- `node --test .claude/hooks/pre.ask.unattended.test.mjs` → 3/3.
- `npm run test:gate` → alle grün (Linux/macOS 57/57).
- Manuell:
  - `echo '{"tool_name":"AskUserQuestion","session_id":"nobody"}' | node .claude/hooks/pre.ask.unattended.mjs; echo $?` → `0`.
  - Mit einem Fake-Record und `CCD_SESSIONS_ROOT` wie im Test → `2` und die Begründung auf stderr.
  - Auf Windows zusätzlich einmal `npm run test:gate`.

### Schritt 2 — devops-Plugin auch in Cloud-Sessions laden (NEU-2)

Datei: `.claude/settings.json`

Änderung: Zwei Top-Level-Schlüssel ergänzen. `permissions`, `env` und `hooks` bleiben unverändert.
```json
"extraKnownMarketplaces": {
  "dotclaude": {
    "source": { "source": "github", "repo": "Jerry0022/dotclaude" }
  }
},
"enabledPlugins": {
  "devops@dotclaude": true
}
```
- `local-llm@dotclaude` **nicht** aktivieren. Es braucht eine lokale AnythingLLM-Instanz, die es in der Cloud nicht gibt. Die user-weite Einstellung auf dem Owner-Rechner bleibt davon unberührt.
- Die Datei hat ein `$schema` (`https://json.schemastore.org/claude-code-settings.json`); beide Schlüssel sind dort definiert. Die JSON-Syntax muss gültig bleiben (keine Kommentare in JSON).
- Was das Plugin in der Cloud beim Session-Start tut (aus `plugins/devops/hooks/hooks.json` des Marketplace):
  - Es klont bzw. aktualisiert den Marketplace (`ss.plugin.update`).
  - Es installiert die MCP-Abhängigkeiten per npm (`ss.mcp.deps`).
  - Es schreibt Laufzeit-Ignores nur in `.git/info/exclude` (`ss.project.setup`), also nicht in getrackte Dateien.
  - Es startet einen Hintergrund-Git-Sync (`ss.git.sync`).
  Alle Hooks haben Timeouts ≤ 20 s. Rechne mit etwas langsameren Cloud-Starts.

Prüfen: `node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json','utf8')); console.log('ok')"`. Die eigentliche Wirkung prüft nur eine **neue** Cloud-Session, siehe „Manuelle Schritte“ 1. Die lokale Session kann das nicht selbst.
