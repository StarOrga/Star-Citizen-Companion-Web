**Neuer Baustein `src/lib/fetch-timeout.ts`** (rein, ohne Electron-Import, damit Vitest es lädt):

```ts
export const DEFAULT_FETCH_TIMEOUT_MS = 60_000;

/** A request that ran past its deadline — an Error, so every existing retry/catch path treats it as transient. */
export class FetchTimeoutError extends Error {
  override readonly name = 'FetchTimeoutError';
  constructor(readonly url: string, readonly ms: number) {
    super(`timeout after ${Math.round(ms / 1000)} s: ${url}`);
  }
}

/** fetch with a deadline that covers headers AND body; a caller's own signal still wins. */
export function fetchWithTimeout(
  input: string | URL,
  init: RequestInit = {},
  ms: number = DEFAULT_FETCH_TIMEOUT_MS,
  fetchImpl: typeof fetch = fetch,
): Promise<Response>;

/** Deadline for a PUT of `bytes`: 60 s plus 1 s per 100 kB (≥ 100 kB/s uplink). */
export function putTimeoutMs(bytes: number): number;

/** A deadline hit — ours (FetchTimeoutError) or the platform's AbortSignal.timeout (DOMException 'TimeoutError'). */
export function isTimeout(err: unknown): boolean;

/** Read a body to the end; abort when no chunk arrives for `stallMs`. */
export function readWithStallTimeout(
  body: ReadableStream<Uint8Array>,
  stallMs: number,
  onChunk: (chunk: Uint8Array) => void,
  url?: string,
): Promise<void>;
```

- `fetchWithTimeout`:
  - Kombiniert `init.signal` und `AbortSignal.timeout(ms)` per `AbortSignal.any`. Electron 44 und Node ≥ 20.3 haben es.
  - Eine Ablehnung mit `name === 'TimeoutError'` wird zu `FetchTimeoutError`, alles andere geht unverändert weiter.
  - Wichtig: `fetchImpl` als Default-Parameter wird **pro Aufruf** ausgewertet. `vi.stubGlobal('fetch', …)` in den bestehenden Specs greift also weiter.
- `readWithStallTimeout`: Ein Timer wird bei jedem Chunk neu gestartet. Läuft er ab → `reader.cancel()` und `FetchTimeoutError`.

Heute stehen an vier Stellen `res.json().catch(() => ({}))` bzw. `.catch(() => [])`: `catalog-bridge.ts` `postOnce`, `token-refresh.ts` `refreshSession`, `sync.ts` `syncServerCatalog` (Zeilenliste) und `skin-ingest.ts` `callIngest`.   - `callIngest`: weiterwerfen, der `catch` pro Schiff übernimmt.
- Ein Watchdog (`createWatchdog`) für die Upload-Stufen ist nicht nötig. Mit den Fristen kann kein Aufruf mehr ewig hängen.

### Schritt 6 – R2-Gate in der Function: gute Messung überbrückt einen Analytics-Aussetzer

**Dateien:**

**Änderung:**

- `_r2-usage.ts` bleibt rein (Kopfkommentar: „Pure logic only … so the Node tests can load it“) und bekommt:

  ```ts
  /** A reading is reused without asking Cloudflare again for this long (was USAGE_TTL_MS in _r2.ts). */
  export const USAGE_TTL_MS = 5 * 60 * 1000;
  /** When Cloudflare cannot be asked, a good reading this old still decides — never older, never from another month. */
  export const USAGE_STALE_MAX_MS = 24 * 60 * 60 * 1000;

  export interface UsageReading { at: number; usage: R2Usage }

  export type UsageGate =
    | { kind: 'ok'; stale: boolean }
    | { kind: 'over'; over: string; stale: boolean } // → 507 r2_free_tier_guard
    | { kind: 'unknown'; reason: string };           // → 503 r2_usage_unknown

  export function isFresh(r: UsageReading | null, now: number): boolean;
  export function usageGate(reading: UsageReading | null, readError: string | null, now: number): UsageGate;
  ```

  Regeln für `usageGate`:
  - Ohne `readError` und mit `reading` → `overLimit(reading.usage)` entscheidet, `stale: false`.
  - Mit `readError` → Die letzte Messung zählt nur, wenn sie höchstens `USAGE_STALE_MAX_MS` alt ist **und** `monthStart(new Date(reading.at)) === monthStart(new Date(now))`, weil der Verbrauch monatlich zurückgesetzt wird. Dann entscheidet `overLimit(reading.usage)` wie oben (`ok` oder `over`), jeweils mit `stale: true`. Sonst `unknown` mit `reason = readError`.
  - `isFresh(r, now)` ist `r !== null && now - r.at < USAGE_TTL_MS`.
  - Keine Messung → `unknown` (fail closed).
- `_r2.ts`: `fetchUsage` wird `readUsage(cfg, now = new Date()): Promise<{ reading: UsageReading | null; error: string | null }>`.
  - Modul-Variable `lastReading: UsageReading | null` statt `usageCache`.
  - `isFresh(lastReading, now.getTime())` → sofort `{ reading: lastReading, error: null }` zurück.
  - Sonst die GraphQL-Abfrage, **mit der Frist aus D12 Schritt 5**. Erfolg → `lastReading` setzen.
  - Fehler → `{ reading: lastReading, error: message }`. `CF_ANALYTICS_TOKEN` fehlt → `error` wie heute.
  - Die alte `USAGE_TTL_MS`-Konstante (~Z. 134) entfernen, sie steht jetzt in `_r2-usage.ts`.
- `index.ts` (~Z. 181–191):

  ```ts
  const { reading, error } = await readUsage(r2);
  const gate = usageGate(reading, error, Date.now());
  if (gate.kind === 'unknown') return json({ error: 'r2_usage_unknown', message: gate.reason }, 503);
  if (gate.stale) console.warn(`ingest-skins: analytics unreadable (${error}); deciding on a reading ${Math.round((Date.now() - reading!.at) / 60000)} min old`);
  if (gate.kind === 'over') return json({ error: 'r2_free_tier_guard', message: `R2 usage near the free tier: ${gate.over}` }, 507);
  ```

  Der Block ersetzt das heutige `try { const over = overLimit(await fetchUsage(r2)); … } catch (e) { … 503 }` (~Z. 181–191). Importe anpassen: aus `./_r2.ts` `readUsage` statt `fetchUsage`, aus `./_r2-usage.ts` `usageGate` dazu. `overLimit` wird in `index.ts` danach nicht mehr gebraucht, den Import entfernen, falls es keinen anderen Nutzer gibt (`grep -n "overLimit" supabase/functions/ingest-skins/index.ts`).

  Den Kopfkommentar (~Z. 33) um „a reading up to 24 h old (same month) bridges an Analytics outage“ ergänzen.
- **Ehrliche Grenze**, als Kommentar an `lastReading`: Die Messung lebt pro Isolate. Sie hilft, solange das Isolate warm ist, also typisch innerhalb eines Upload-Laufs mit ~150 `sign`-Aufrufen. Ein Kaltstart ohne Messung bleibt fail-closed. Eine persistente Messung (DB) wäre eine eigene Entscheidung, siehe „Bewusst nicht Teil“.
- `_r2-usage.test.mjs`, neues `describe('usageGate')`:
  - Frisch und unter den Grenzen → `ok`.
  - Frisch und drüber → `over` mit Text.
  - Fehler + Messung 2 h alt, gleicher Monat → `ok`, `stale: true`.
  - Fehler + 25 h alt → `unknown`.
  - Fehler + Messung vom 31. des Vormonats um 23:00 UTC, jetzt der 1. um 01:00 UTC (also nur 2 h alt, aber anderer Monat) → `unknown`.
  - Fehler + Messung 2 h alt, gleicher Monat, aber über den Grenzen → `over`, `stale: true`.
  - Fehler ohne Messung → `unknown`.
  - Dazu `describe('isFresh')`: 4:59 min → `true`, 5:01 min → `false`.
