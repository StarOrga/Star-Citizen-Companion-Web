## Ziel und Definition of Done

- Auf einem Touch-Gerät rendert jedes Text-Eingabefeld (`input` außer Checkbox/Radio/Range/File/Color/Button-Typen, `textarea`, natives `select`) mit mindestens 16 px. iOS Safari zoomt beim Antippen eines Suchfelds nicht mehr hinein. Auf dem Desktop bleiben alle Feldgrößen unverändert.
- `npm run gate:mobile:selftest` meldet den neuen Check `input-zoom` als `ok`. `npm run gate:mobile` und `npm run gate:mobile:auth` melden auf `iphone-14` keinen `input-zoom`-Befund.
- `:root` erklärt `color-scheme: dark`, `src/index.html` hat `<meta name="color-scheme" content="dark">`. Native Popups, Spinner, Autofill und Scrollbar-Ecken sind dunkel.
- Holotable-Leiste (alle Breiten), ihr Bottom-Sheet (≤ 640 px), Vergleichsleiste, Undo-Toast und Lade-Hinweis `.nav-scan__label` halten den Home-Indikator frei. Das Sheet nutzt `70dvh`.
- `grep -rn "100vh" src/app --include=*.ts | grep -v '\.spec\.ts'` findet nur noch Fallback-Zeilen, auf die direkt eine `dvh`-Zeile folgt (heute nur `patch-dossier.component.ts`).
- `/set-password` setzt am Wurzelelement kein vertikales `padding`. Die Karte beginnt auf derselben Linie wie die anderen öffentlichen Seiten.
- Segmented Control, Holotable-Leiste, Einsatz-Leiste, Settings-TOC (Handy) und Dossier-TOC (Handy) zeigen einen Randverlauf, sobald Inhalt über den Rand ragt. Am Anfang oder Ende der Scrollstrecke verschwindet der Verlauf. Die lokale Scrollbar-Sonderform in `codex-bridge.component.ts` ist weg.
- `npm run typecheck`, `npm test`, `npm run build` grün, **ohne neue Budget-Warnung** (`anyComponentStyle`, Warnschwelle 18 kB).
  - Knapp ist `codex/codex-detail.component.ts`: am `1b08612` gemessen 17,95 kB Komponenten-CSS, also rund 50 B Luft. Schritt 2 fügt dort nur `.sl-input` hinzu (+~24 B minifiziert).   // iOS Safari zooms the whole page when a text field with font-size < 16px
  ```js
  // takes focus. Only iOS does this, so only iOS devices report it.
  if (opts.os === 'iOS') {
    const MIN_IN = opts.minInputFontSizePx;
    const fields = document.querySelectorAll(
      'input:not([type="hidden"]):not([type="checkbox"]):not([type="radio"]):not([type="range"])' +
      ':not([type="file"]):not([type="color"]):not([type="button"]):not([type="submit"])' +
      ':not([type="reset"]):not([type="image"]),textarea,select');
    for (let i = 0; i < fields.length; i++) {
      const el = fields[i];
      if (el.disabled || el.readOnly || !rendered(el)) continue;
      const fs = parseFloat(getComputedStyle(el).fontSize);
      if (!(fs < MIN_IN - 0.01)) continue;
      add('input-zoom', 'text field renders at ' + fs + 'px (< ' + MIN_IN + 'px) — iOS Safari zooms on focus', el, {
        detail: String(fs), measured: fs, limit: MIN_IN, text: label(el),
      });
    }
  }
  ```

### Schritt 8 – Baustein `ScScrollHintDirective` (Randverlauf nur bei echtem Überlauf)

**Dateien:** neu `src/app/shared/scroll-hint.directive.ts`, neu `src/app/shared/scroll-hint.directive.spec.ts`, `src/styles.scss`.

**Änderung:**
- Direktive, standalone, im Stil von `src/app/shared/tooltip/sc-tooltip.directive.ts` (signals, `inject`, `DestroyRef`):

  ```ts
  /**
   * Marks a horizontally scrolling strip with where there is more to scroll, so
   * the global `.sc-scroll-hint` rule (styles.scss) can fade exactly those edges.
   * A hidden scrollbar alone gives a mouse user no cue that a strip scrolls
   * (audit AUD-160/220/281); a permanent fade lies at either end.
   */
  @Directive({
    selector: '[scScrollHint]',
    standalone: true,
    host: {
      class: 'sc-scroll-hint',
      '[attr.data-more-start]': 'moreStart() ? "" : null',
      '[attr.data-more-end]': 'moreEnd() ? "" : null',
    },
  })
  export class ScScrollHintDirective {
    private readonly el = inject<ElementRef<HTMLElement>>(ElementRef);
    private readonly zone = inject(NgZone);
    readonly moreStart = signal(false);
    readonly moreEnd = signal(false);
    constructor() {
      afterNextRender(() => { /* measure(); then, inside
        this.zone.runOutsideAngular(): el.addEventListener('scroll', measure,
        { passive: true }); ResizeObserver on the element AND its direct children
        (content can grow without the box growing); MutationObserver(childList)
        re-observes new children. Listener removed and both observers
        disconnected via inject(DestroyRef).onDestroy */ });
    }
    measure(): void {
      const e = this.el.nativeElement;
      const x = Math.abs(e.scrollLeft);                 // RTL-safe
      const max = e.scrollWidth - e.clientWidth;
      this.moreStart.set(x > 1);
      this.moreEnd.set(max - x > 1);
    }
  }
  ```

  Ohne `ResizeObserver` (alte Engine, Test-Stub) einmal messen und fertig.
  - **Den Scroll-Listener nicht als Host-Listener `'(scroll)'` binden.** Die App läuft mit zone.js (`provideZoneChangeDetection` in `app.config.ts`); ein Template-/Host-Listener löst bei jedem Scroll-Event einen App-Tick aus. Deshalb `addEventListener` außerhalb der Zone. Die Signale ändern sich nur an den Rändern der Scrollstrecke (`signal.set` mit gleichem Wert benachrichtigt niemanden), und eine Signal-Änderung plant in Angular 22 auch außerhalb der Zone ein Rendern ein. So kostet ein Scroll-Event keine Change Detection, solange sich nichts ändert.
- `src/styles.scss`, direkt nach dem Scrollbar-Block (~Z. 555–582):

  ```scss
     sets data-more-start / data-more-end on a sideways-scrolling strip; the
     edge that has more content fades out. No attribute, no fade: at either end
     of the strip the edge is hard again. */
  .sc-scroll-hint { --sc-scroll-fade: 24px; }

            mask-image: linear-gradient(90deg, transparent, #000 var(--sc-scroll-fade), #000 calc(100% - var(--sc-scroll-fade)), transparent);
  }
  ```
