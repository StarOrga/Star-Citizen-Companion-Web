  - Linksklick navigiert wie bisher.

  - Der Kommentar „A column is a BUTTON …“ ist korrigiert.

  - Die Patch-Tooltips zeigen ein lokalisiertes Datum statt ISO.
  - Der Offensiv-Hinweis ist übersetzt.

#### Schritt 3 · Weiterleitungen behalten die Query — festhalten statt umbauen (AUD-144)

**Befund veraltet bzw. Fehlbefund:** AUD-144 nimmt an, Angular 22 behalte bei String-Redirects nur die im Ziel genannten Params. Das gilt nur für **absolute** Ziele (`'/…'`). Alle fünf betroffenen Routen sind relativ und reichen Query und Fragment schon heute weiter (Beleg in „Vorab prüfen“ Punkt 4). Die Option „Weiterleitungen mit Query“ ist damit erfüllt. Dieser Schritt ändert keine Route, er sichert das Verhalten ab:

- `src/app/app.routes.ts`: über den fünf Routen (`''`, `p4k`, `desktop`, `admin/integrations`, `'**'`) je einen kurzen Kommentar bzw. einen gemeinsamen Absatz über `routes`: „Relative string redirect on purpose: Angular keeps the incoming query + fragment for a relative `redirectTo` (`/?item=<id>` → `/news?item=<id>`). Never prefix the target with `/` — an absolute string redirect drops the query (see blueprintListRedirect). Pinned in app.routes.spec.ts.“
- `src/app/app.routes.spec.ts`, neuer `describe('string redirects keep the query (AUD-144)')`:
  - Die fünf Redirect-Einträge aus dem echten `routes`-Array holen: Root-`''` mit `redirectTo` und `'**'` aus `routes`, `p4k`, `desktop` und `admin/integrations` aus den `children` des Shell-Eintrags (dem `''`-Eintrag mit `children`).
  - Einen Test-Router aufbauen, der **nur** diese Einträge plus Platzhalter-Ziele enthält (keine Guards, keine Lazy-Komponenten): `provideRouter([rootRedirect, { path: '', children: [{ path: 'news', children: [] }, { path: 'uploader', children: [] }, { path: 'admin/api-tokens', children: [] }, p4k, desktop, integrations] }, wildcard])` plus `provideLocationMocks()` aus `@angular/common/testing`, damit die Navigation die Karma-URL nicht anfasst.
  - Je Fall `await router.navigateByUrl(…)` und `expect(router.url)`: `/?item=abc#x` → `/news?item=abc#x`, `/p4k?x=1` → `/uploader?x=1`, `/desktop?x=1` → `/uploader?x=1`, `/admin/integrations?y=2` → `/admin/api-tokens?y=2`, `/gibtsnicht?item=z` → `/news?item=z`.
  - Zusätzlich je Eintrag `expect(typeof r.redirectTo === 'string' && !r.redirectTo.startsWith('/')).toBeTrue()`, damit ein späterer absoluter Umbau sofort auffällt.
- **Nur falls** eine dieser Specs rot ist (z. B. nach einem Angular-Update hat sich das Verhalten geändert): dann erst die fünf Routen auf einen funktionalen Redirect umstellen, nach dem Muster von `blueprintListRedirect` in derselben Datei:
  ```ts
  export function keepQueryRedirect(target: string): RedirectFunction {
    return ({ queryParams, fragment }) =>
      inject(Router).createUrlTree([target], { queryParams, fragment: fragment ?? undefined });
  }
  ```
  mit absoluten Zielen (`'/news'`, `'/uploader'`, `'/admin/api-tokens'`), `RedirectFunction` aus `@angular/router`. Die Spec oben bleibt dieselbe, nur die `startsWith('/')`-Zeile entfällt dann.
- Prüfen: `http://127.0.0.1:4200/?item=<eine echte News-ID aus /news>` landet auf `/news?item=<id>`, der Beitrag ist geöffnet. `/p4k?x=1` landet auf `/uploader?x=1`.

#### Schritt 5 · Locale nach Kontowechsel neu anwenden (AUD-198)

- `src/app/app.component.ts`:
  - `private appliedProfileLocale = false;` wird zu `private appliedProfileFor: string | null = null;`. Den Doc-Kommentar anpassen: einmal **pro Konto**, nicht pro Dokument.
  - Der Effekt:
    ```ts
    const user = this.auth.user();
    if (!user) {
      if (this.appliedProfileFor !== null) { this.appliedProfileFor = null; this.locale.clearProfile(); }
      return;
    }
    if (this.appliedProfileFor === user.id) return;
    this.appliedProfileFor = user.id;
    // …select wie bisher…, im .then zuerst: if (this.appliedProfileFor !== user.id) return;
    ```

    Der Vergleich im `.then` verhindert, dass eine späte Antwort für Konto A nach dem Wechsel zu B noch angewendet wird. Nur aufräumen, wenn vorher ein Profil angewendet wurde. So bleibt der Boot (`user()` ist anfangs `null`) unberührt.
