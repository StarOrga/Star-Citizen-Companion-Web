## Entscheidung

- **Gewählt: Option A – „Dialog-Baustein und Grundgerüst“**: „Eine gemeinsame Direktive (Fokus rein, Tab bleibt drin, Escape schließt, Fokus zurück) für alle neun Dialoge. Skip-Link. Hauptüberschrift auf Set-Seite und Codex-Start. Tooltip-Anker werden fokussierbar.“
- Das ist die Empfehlung des Audits, **keine Abweichung**. Keine Owner-Notiz. Allgemeine Owner-Vorgabe: teilbare Umsetzungspläne statt Umsetzung – deshalb dieses Dokument.
- Wie der Plan das umsetzt:
  - **Die gemeinsame Direktive** ist `ScDialogDirective` aus D03 Schritt 1 (`src/app/shared/dialog/sc-dialog.directive.ts`). Sie wird hier nicht neu gebaut, nur angewendet.
  - **Die neun Dialoge** (auf main 0.104.1 verifiziert, keiner nimmt den Fokus auf, hält ihn und gibt ihn zurück):
    1. News-Artikel-Detail – `src/app/news/news-list.component.ts` (`.nd-panel`)
    2. Patch-Dossier – `src/app/news/patch-dossier.component.ts` (`.panel`)
    3. Schnellsuche – `src/app/shell/quick-search.component.ts` (`.panel`)
    4. Status-Popover im Header – `src/app/news/verse-status-chip.component.ts` (`.vs-panel`, nicht modal)
    5. Starscape-Lightbox – `src/app/starscape/starscape.component.ts` (`.lightbox`)
    6. Bundle-Historie auf der Download-Seite – `src/app/desktop/desktop-download.component.ts` (`.hx-dialog`)
    7. Bundle-Historie im Uploader-Zugang – `src/app/desktop/uploader-access.component.ts` (`.hx-dialog`)
    8. API-Token anlegen – `src/app/admin/api-tokens/api-tokens.component.ts` (`.dialog`)
    9. API-Token anzeigen – ebenda (`.reveal-dialog`)
  - **„Tooltip-Anker werden fokussierbar“** heißt: Wo ein App-Tooltip die einzige Quelle einer Information ist, wird sein Anker per Tastatur erreichbar. Ausnahme mit Absicht: Anker **innerhalb** eines Links oder Knopfs bekommen keinen eigenen Tab-Stopp – das wäre verschachtelte Interaktion, genau der Fehler aus AUD-070. Dort wandert die Information in den Namen des umgebenden Elements oder bleibt Zusatzinfo. So empfiehlt es auch der Fix-Text von AUD-084.
  - Die übrigen Punkte des Blocks (Radiogruppen, Touch-Ziele, Kontomenü u. a.) deckt Option A nicht ab → „Bewusst nicht Teil“ mit Empfehlung.

## Ziel und Definition of Done

- Alle neun Dialoge: Beim Öffnen springt der Fokus hinein, Tab/Shift+Tab kreisen darin (die acht modalen), Escape schließt, danach steht der Fokus wieder auf dem Element, das den Dialog geöffnet hat. Einzige gewollte Ausnahme: Im API-Token-Anzeige-Dialog schließt Escape erst, nachdem das Token kopiert wurde (Schritt 5, Schutz vor Token-Verlust).
- Die modalen Dialoge tragen `aria-modal="true"` und einen Namen (`aria-label` oder `aria-labelledby`).
- Jede Seite in Shell und öffentlichem Layout hat als ersten Tab-Stopp „Zum Inhalt springen“; Enter setzt den Fokus auf `<main id="sc-main">`, ohne die URL zu verändern.
- `/codex` und `/codex/set/:id` haben je genau ein `<h1>`; auf der Set-Seite ist es der sichtbare Set-Name.
- Tooltip-Anker: Der Scan aus Schritt 7 zeigt keinen Anker der Kategorien A/B mehr ohne Entscheidung; die im Audit genannten Beispiele (AUD-084, AUD-119) sind per Tastatur erreichbar.
- Globale Hilfsklasse `.sc-sr-only` in `src/styles.scss` (D08 nutzt sie).
- `npm run typecheck`, `npm test`, `npm run build` grün.

```js

import fs from 'node:fs'; import path from 'node:path';
const ROOT = process.argv[2] ?? 'src/app';
const walk = (d) => fs.readdirSync(d, { withFileTypes: true }).flatMap((e) => {
  const p = path.join(d, e.name);
  return e.isDirectory() ? walk(p) : p.endsWith('.ts') && !p.endsWith('.spec.ts') ? [p] : [];
});
const OPEN = /<(span|div|li|td|th|dd|dt|i|b|p|label|h[1-6]|g|svg|strong|small)\b((?:[^<>"]|"[^"]*")*?)>/g;
const rows = [];
for (const f of walk(ROOT)) {
  const s = fs.readFileSync(f, 'utf8');
  let m;
  while ((m = OPEN.exec(s))) {
    const [whole, tag, attrs] = m;
    if (!/\[?scTooltip\]?\s*=/.test(attrs) || /tabindex/.test(attrs)) continue;
    const line = s.slice(0, m.index).split('\n').length;
    const before = s.slice(Math.max(0, s.lastIndexOf('template:', m.index)), m.index).replace(/<!--[\s\S]*?-->/g, '');
    const depth = (t) => (before.match(new RegExp(`<${t}\\b`, 'g')) ?? []).length - (before.match(new RegExp(`</${t}>`, 'g')) ?? []).length;
    const inside = depth('a') > 0 || depth('button') > 0;
    const after = s.slice(m.index + whole.length, m.index + whole.length + 600);
    const close = after.indexOf(`</${tag}>`);
    const body = close >= 0 ? after.slice(0, close) : '';
    const wraps = /<(button|a|input|select|textarea|sc-select)\b/.test(body) || /display:\s*contents/.test(attrs) || /tip-wrap|chip-wrap/.test(attrs);
    const cat = wraps ? 'W' : inside ? 'N' : /role="img"|aria-label/.test(attrs) ? 'A' : 'B';
    rows.push(`${cat}  ${f}:${line}  <${tag}> ${attrs.replace(/\s+/g, ' ').trim().slice(0, 110)}`);
  }
}
rows.sort();
console.log(rows.join('\n'));
console.log(`\n${rows.length} Anker · W=umschließt Bedienelement · N=in <a>/<button> · A=hat schon Name/role · B=frei`);
```

Stand 0.104.1: 81 Anker – 13 × W, 22 × N, 8 × A, 38 × B.

**b) Regeln** (pro Zeile genau eine Entscheidung, die Liste kommt in die PR-Beschreibung):

| Kategorie | Bedeutung | Entscheidung |
|---|---|---|
| W | Wrapper um ein Bedienelement (`tip-wrap`, `chip-wrap`, `display: contents`) | nichts tun – `focusin` des inneren Elements öffnet den Tooltip. Ausnahme dokumentieren: umschließt der Wrapper einen `[disabled]`-Knopf, ist der Grund per Tastatur nicht erreichbar (→ „Bewusst nicht Teil“). |
| N | liegt in einem `<a>` oder `<button>` | **kein** `tabindex`. Steht die Information sonst nirgends und ist sie kurz, als `<span class="sc-sr-only">` in den Anker schreiben (sie wird Teil des Link-/Knopfnamens); sonst unverändert lassen. |
| A | Symbol ohne eigenen Text, hat schon `aria-label`/`role` | Muster A (unten): `tabindex="0"` ergänzen, ggf. `role="img"`. |
| B, Text sichtbar | Element zeigt Text, Tooltip ergänzt | Wiederholt der Tooltip nur den sichtbaren Text → Tooltip streichen (REQ-8). Sonst `tabindex="0"` ergänzen: Der sichtbare Text bleibt der Name, der Tooltip öffnet bei Tastaturfokus sofort und setzt `aria-describedby` (`sc-tooltip.directive.ts` `onFocus`/`applyDescribedBy`). |
| B, nur Symbol/Strich | „—“, Punkt, Icon | Muster A. |
| C | Punkte einer Diagramm-Reihe (`patch-cadence` `.col`, `patch-cycle` `.pt`, `stability-panel` `.col`) | kein Tab-Stopp pro Punkt. Prüfen, ob das Label des Diagramm-Containers (`role="img"`) die Werte nennt; wenn nicht (z. B. `stability-panel.component.ts:66` nennt nur die Tageszahl), die Werte ins Label oder in eine `sc-sr-only`-Liste nach dem Diagramm – Muster wie D08 Schritt 6. |

Muster A:

```html
<span class="gap-dash" tabindex="0" role="img"
      [attr.aria-label]="reason" [scTooltip]="reason" scTooltipTier="label">—</span>
```

Ist `aria-label` gleich dem Tooltip-Text, setzt die Direktive kein zusätzliches `aria-describedby` – nichts wird doppelt vorgelesen.
