## Entscheidung

- **Gewählt: Option A – „App-Dialog und ehrliches Konto-Löschen“**: „Ein eigener Bestätigungsdialog ersetzt alle neun Browser-Dialoge und schützt die Hangar-Löschungen. Für Nicht-Admins ersetzt ein Hinweis mit Link zum Impressum den Löschknopf, passend zur Datenschutzerklärung.“
- Das ist die Empfehlung des Audits, **keine Abweichung**. Keine Owner-Notiz zu diesem Block. Allgemeine Owner-Vorgabe: teilbare Umsetzungspläne statt Umsetzung – deshalb dieses Dokument.
- Wie der Plan das umsetzt:
  - Auf main (0.104.1) sind es **zehn** native Aufrufe (neun `window.confirm`, ein `window.prompt`) in sechs Dateien. „Neun Browser-Dialoge“ im Entscheidungskonzept (`docs/concepts/2026-09-27-audit-0104-entscheidungen.html`) zählt den `prompt` nicht mit; ersetzt werden alle zehn.

  - Die Edge Function `supabase/functions/delete-user` bleibt **unverändert** (Selbstlöschung für Nicht-Admins wäre Option B). Nicht-Admins sehen stattdessen den Hinweis mit Link auf `/legal/imprint`; der Text deckt sich mit `legal.privacy.rights.p2` („Ausgeführt wird die Löschung derzeit von einem Administrator …“).
  - AUD-035 und AUD-197 gehören zum Block, sind aber keine Rückfrage-Dialoge und von Option A nicht erfasst → „Bewusst nicht Teil“.

## Schritte

### Schritt 1 – Gemeinsamer Baustein `ScDialogDirective`

**Dateien:** neu `src/app/shared/dialog/sc-dialog.directive.ts`, `src/app/shared/dialog/sc-dialog.directive.spec.ts` (Ordner nach dem Vorbild `src/app/shared/tooltip/`); geändert `src/styles.scss` (eine Regel, siehe unten).

**Änderung:** Eine Attribut-Direktive für jedes Dialog-Element. Sie ist die eine Stelle für „Fokus rein, Tab bleibt drin, Escape, Fokus zurück“ und ersetzt auf Dauer die drei handgeschriebenen Varianten (`src/app/codex/codex-component-modal.component.ts` `onKeydown`, `codex-weapon-detail.component.ts`, `codex-swap-picker.component.ts` – die bleiben in diesem Plan unangetastet).

Verbindliche API (D07 baut darauf auf):

```ts
// src/app/shared/dialog/sc-dialog.directive.ts
@Directive({ selector: '[scDialog]', standalone: true, host: { class: 'sc-dialog', '(keydown)': 'onKeydown($event)' } })
export class ScDialogDirective implements OnDestroy {
  /** true (Standard): Tab/Shift+Tab bleiben im Dialog. false: nicht-modales Popover – nur Fokus rein, Escape, Fokus zurück. */
  readonly scDialogModal = input(true);
  /** 'first': Element mit Attribut cdkFocusInitial, sonst erstes tabbares Element, sonst der Dialog selbst. 'container': der Dialog selbst. */
  readonly scDialogInitialFocus = input<'first' | 'container'>('first');
  /** Explizites Rücksprungziel; Standard ist das Element, das beim Öffnen den Fokus hatte. */
  readonly scDialogReturnFocus = input<HTMLElement | null>(null);
  /** Escape im Dialog. Der Host entscheidet, was „schließen“ heißt. */
  readonly scDialogEscape = output<void>();
}
```

Verhalten:

- **Öffnen = Konstruktion.** Die Direktive sitzt auf einem Element, das per `@if` oder CDK-Portal entsteht. Im Konstruktor `document.activeElement` als Opener merken; fehlt am Host ein `tabindex`, `tabindex="-1"` setzen (dann kann der Dialog selbst den Fokus halten, auch nach einem Klick auf nicht fokussierbaren Inhalt).
- **Fokus rein** in `afterNextRender`: `FocusTrapFactory.create(host)` aus `@angular/cdk/a11y` anlegen und `trap.enabled = scDialogModal()` setzen. Bei `'container'` den Host fokussieren, sonst `trap.focusInitialElement()` (beachtet `[cdkFocusInitial]`, fällt auf das erste tabbare Element zurück); liefert das `false`, den Host fokussieren. Immer `{ preventScroll: true }`, wo es geht.
- **Tab bleibt drin:** über die CDK-Anker (`.cdk-focus-trap-anchor`) – kein eigener Tab-Zähler. Das erfasst auch `select`, `textarea`, versteckte und `disabled` Elemente korrekt, was die handgeschriebenen Selektoren nicht tun.
- **Escape** über den Host-`keydown`, **nicht** über `document`: ist `ev.defaultPrevented`, nichts tun (ein inneres Widget hat die Taste schon verbraucht – `sc-select` ruft bei offener Liste `preventDefault()` + `stopPropagation()`, `sc-tooltip` bei offenem Tooltip `stopPropagation()`; in beiden Fällen kommt Escape gar nicht erst oder mit `defaultPrevented` am Host an). Sonst `preventDefault()`, `stopPropagation()` und `scDialogEscape.emit()`. Grund: So schließt Escape in einem gestapelten Dialog (Bestätigung über der Bundle-Historie) nur den obersten, und document-weite Escape-Handler der Seite (Kontomenü, Feedback-FAB) feuern nicht mit.
- **Fokus zurück** in `ngOnDestroy`: `trap.destroy()`, dann in `requestAnimationFrame` (bis dahin ist ein zuvor gesperrter Auslöser wieder aktiv): Ziel = `scDialogReturnFocus() ?? opener`. Nur zurückspringen, wenn `document.activeElement` `null` oder `document.body` ist (der Fokus ist mit dem Dialog verschwunden), das Ziel `isConnected` ist und nicht `:disabled`. So stiehlt die Direktive keinen Fokus, wenn der Nutzer außerhalb auf ein anderes Bedienelement geklickt hat oder schon ein Folgedialog den Fokus hält.
- Kopfkommentar im Stil von `sc-tooltip.directive.ts`: wofür, warum Host-Keydown statt Document, warum rAF.
- **Kein Rahmen um den ganzen Dialog:** Wird der Dialog-Container selbst fokussiert (`'container'`, oder `'first'` ohne tabbares Element), greift nach einer Tastatur-Aktion die globale Regel `:focus-visible { outline: 2px solid var(--sc-accent) }` (`src/styles.scss` ~Z. 527) und zeichnet einen Rahmen um Lightbox, Panel oder Popover. Deshalb in `src/styles.scss` direkt unter diese Regel: `.sc-dialog:focus { outline: none; }` (mit Kommentar: Container mit `tabindex="-1"` ist kein Tab-Stopp, sein Fokus ist nur Ausgangspunkt für Screenreader und Tab). Die Klasse setzt die Direktive selbst (`host: { class: 'sc-dialog' }`, siehe API); Bedienelemente im Dialog behalten ihren Fokusrahmen.

**Spec** (Jasmine, Host-Component wie in `src/app/shared/sc-select.component.spec.ts`; nach `fixture.detectChanges()` ein `await fixture.whenStable()` für `afterNextRender`, für den Rücksprung `await new Promise(r => requestAnimationFrame(r))`):

1. Öffnen fokussiert das erste tabbare Element.
2. `cdkFocusInitial` gewinnt.
3. `scDialogInitialFocus="container"` fokussiert den Host; der Host hat `tabindex="-1"` und die Klasse `sc-dialog`.
4. Modal: vor und nach dem Host liegen `.cdk-focus-trap-anchor`; `endAnchor.focus()` setzt den Fokus auf das erste tabbare Element. Nicht modal: Anker sind deaktiviert (`tabindex` fehlt bzw. `-1`).
5. Escape emittiert genau einmal; ein `document`-Keydown-Spy sieht das Event nicht.
6. Escape mit `defaultPrevented` emittiert nicht.
7. Schließen (`@if` auf false) setzt den Fokus zurück auf den Opener; hatte vorher ein anderer Knopf außerhalb den Fokus, bleibt er dort.
8. `scDialogReturnFocus` gewinnt gegen den Opener.

**Schließt:** Grundlage für AUD-088/AUD-288 (Fokusfalle, Escape). **Prüfen:** `npm test -- --include='src/app/shared/dialog/**/*.spec.ts'`, `npm run typecheck`.

### Schritt 2 – `ScConfirmService` und `sc-confirm-dialog`

**Dateien:** neu `src/app/shared/dialog/sc-confirm.service.ts`, `src/app/shared/dialog/sc-confirm-dialog.component.ts`, `src/app/shared/dialog/sc-confirm.service.spec.ts`; geändert `src/styles.scss`, `public/i18n/de.json`, `public/i18n/en.json`.

**a) API** (im Service-File exportiert):

```ts
export type ScConfirmTone = 'default' | 'danger';
export interface ScConfirmOptions {
  readonly titleKey: string;
  readonly messageKey?: string;
  /** Interpolationsparameter für titleKey UND messageKey. */
  readonly params?: Record<string, unknown>;
  readonly confirmKey?: string;   // Standard 'common.dialog.confirm'
  readonly cancelKey?: string;    // Standard 'common.dialog.cancel'
  readonly tone?: ScConfirmTone;  // Standard 'default'
}
export interface ScPromptOptions extends ScConfirmOptions {
  readonly inputLabelKey: string;
  readonly inputMaxLength?: number;
}
@Injectable({ providedIn: 'root' })
export class ScConfirmService {
  confirm(o: ScConfirmOptions): Promise<boolean>;
  /** null = abgebrochen, '' = bestätigt ohne Text. Der Aufrufer trimmt selbst. */
  prompt(o: ScPromptOptions): Promise<string | null>;
}
```

**b) Service:** CDK-Overlay wie in `src/app/shared/tooltip/sc-tooltip.directive.ts` (`Overlay`, `ComponentPortal`): `hasBackdrop: true`, `backdropClass: 'sc-dialog-backdrop'`, `panelClass: 'sc-dialog-pane'`, `positionStrategy: overlay.position().global().centerHorizontally().centerVertically()`, `scrollStrategy: overlay.scrollStrategies.block()`, `disposeOnNavigation: true`. Inputs per `componentRef.setInput(...)`. Das Promise löst auf bei: `closed`-Output der Komponente, `backdropClick()` (= Abbrechen), `detachments()` (Navigation = Abbrechen). Danach `overlayRef.dispose()`. **Nur ein Dialog gleichzeitig:** ein zweiter Aufruf, während einer offen ist, löst sofort als „abgebrochen“ auf (Doppelklick auf „Löschen“ öffnet keinen zweiten).

**c) Komponente** `sc-confirm-dialog` (standalone, `OnPush`, Inputs als Signal-Inputs, imports `TranslatePipe`, `ScDialogDirective`):

- Inputs (alle Signal-Inputs, im Template also **mit** Klammern aufrufen – ein nicht aufgerufenes Signal ist immer „wahr“ und kompiliert trotzdem): `titleKey = input.required<string>()`, `messageKey = input<string | undefined>()`, `params = input<Record<string, unknown> | undefined>()`, `confirmKey`, `cancelKey`, `tone = input<ScConfirmTone>('default')`, `mode = input<'confirm' | 'prompt'>('confirm')`, `inputLabelKey`, `inputMaxLength`. Output `closed = output<string | null>()`. IDs pro Instanz über einen Modul-Zähler (`let uid = 0;` wie in `sc-select.component.ts`): ``readonly titleId = `sc-confirm-title-${++uid}`;``, `messageId` analog. Der Eingabetext im Prompt-Modus liegt in `readonly text = signal('')`, gesetzt per `(input)` am Feld.
- Wurzel: `<form class="sc-confirm sc-card" scDialog role="alertdialog" aria-modal="true" [attr.aria-labelledby]="titleId" [attr.aria-describedby]="messageKey() ? messageId : null" (scDialogEscape)="closed.emit(null)" (submit)="onSubmit($event)">`. `onSubmit(ev: Event)` ruft zuerst `ev.preventDefault()` (ohne `FormsModule` ist das ein echtes `<form>` – sonst lädt der Browser die Seite neu), dann `closed.emit(mode() === 'prompt' ? text() : '')`.
- `<h2 [id]="titleId">{{ titleKey() | translate: params() }}</h2>`, darunter `@if (messageKey(); as m) { <p [id]="messageId" class="msg">{{ m | translate: params() }}</p> }` mit `white-space: pre-line` (die Bundle-Texte enthalten `\n\n`).
- Im Prompt-Modus ein `<label>` mit `<input class="sc-input" cdkFocusInitial [attr.maxlength]="inputMaxLength() ?? null">` (globale Klasse `.sc-input` aus `src/styles.scss`; `cdkFocusInitial` ist hier ein reines Attribut, die CDK-Fokusfalle sucht per `querySelector('[cdkFocusInitial]')` danach – kein Import nötig).
- Aktionen: `<button type="button" class="sc-btn" (click)="closed.emit(null)">` Abbrechen und `<button type="submit" class="sc-btn sc-btn-primary" [class.danger]="tone() === 'danger'">` Bestätigen. Erstfokus per `[attr.cdkFocusInitial]="… ? '' : null"`: bei `danger` auf **Abbrechen** (sichere Voreinstellung – Enter bricht ab), bei `default` auf Bestätigen, im Prompt auf das Eingabefeld. Bestätigen emittiert `''`/Text, Abbrechen `null`; der Service macht daraus `true`/`false` bzw. Text/`null`.
- Styles in der Komponente: `inline-size: min(440px, calc(100vw - 32px))`, Aktionen `display: flex; flex-wrap: wrap; justify-content: flex-end; gap: 8px`, unter 480 px Knöpfe `flex: 1 1 100%`. Danger-Variante mit `--sc-danger` (CLAUDE.md: reserviert für Fehler und zerstörerische Aktionen) – **nie** `--sc-accent-hot`. `prefers-reduced-motion` respektieren, falls eine Einblend-Animation dazukommt.
