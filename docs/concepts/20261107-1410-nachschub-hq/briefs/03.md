## Why this round
In round 2 the user confirmed every area claim and wrote in the general note: „als nächstes dann gern ein devops cocnetp mit design pure!“ — then chose "erst Design-Concept, dann umsetzen". So: mockups only, and every screen must show the decided behaviour.

## Designs: 3 competing directions (`data-design-set="alternatives"`)
Each design gets a motto, three traits and an icon (overview attributes). Pick three clearly different directions that all fit the app (dark sci-fi, Star Citizen companion). Suggested, change if you have better ones:
- **A „Frachtbrief“** — manifest / cargo-docket look: lists with SCU-style quantities, stamps for states, package = a docket.
- **B „Holo-Tafel“** — the HQ holotable language: packages as slots on a board, glowing nodes, Einsatz chains as routes.
- **C „Leise Liste“** — minimal and dense: plain rows, quiet badges, maximum information per pixel, nothing decorative.

App look: use the real tokens from `src/styles.scss` (`--sc-accent`, `--sc-accent-hot` is ONLY for admin/elevated access — never for these surfaces, `--sc-warning`, `--sc-danger` only for destructive), Orbitron headings like the head.html already embeds. Namespace mock CSS per the design rules.

Selected package: its lines (Menge, Quelle, done state), its 1–x Einsätze with KI names (≤ 40 chars, e.g. „Bergbau-Runde Daymar“, „Einkauf Area18“), route, and „Nachschub leeren → zurück auf die Wunschliste“ (secondary, with undo). Show the Sammlung tab content in at least one design: Blaupausen, Ruf (empty state „noch keine Datenquelle“), News (collected), Galerie (up-voted wallpapers), all quietly. „Ingame-Bestand zurücksetzen“ sits in a page menu (danger, with confirm) — just show where.
6. **Codex: Suchzeile + Detailseite**: two nodes only (Wunschliste with count/quantity, Besitz = Inventar/Hangar/Sammlung by kind). Detail page: quantity stepper next to the wish node. No Nachschub node anywhere. A row that is in a package shows nothing extra (Nachschub lives in HQ).

## Viewports
Desktop is the main target; the app also has a phone gate. Declare desktop + phone (`data-viewports`), default desktop, and make screen 1, 2 and 4 readable on phone (panel as a bottom sheet on phone, positioned with the safe area — the app rule: nothing floats under the feedback launcher).

## Project rules the mocks must respect
- Navigations are real anchors; actions are buttons. One primary action per page/dialog; secondary = pill; tertiary = icon only with tooltip.
- No native selects/dialogs; dialogs get focus handling (just show them as dialogs).
- Red (`--sc-accent-hot`) never on these surfaces.
- A worse comparison value uses warning, never danger.
