§ 2Supabase Auth — NavigatorLockAcquireTimeoutError

Konsole zeigt beim Login-Seite-Render: "Acquiring an exclusive Navigator LockManager lock 'lock:sc.auth' immediately failed". Verifiziert in Preview-MCP-Iframe (lädt Page potenziell doppelt → zwei konkurrierende Supabase-Clients fighten um den Lock).

DIAG

Erst im echten Browser verifizieren

Symptome im Preview-MCP-Frame können Artefakte sein — Vite-Connect und ngx-translate-Warnings traten doppelt auf, was auf zwei Bootstrap-Instanzen hindeutet. Im Single-Tab-Production-Build sollte der Lock-Konflikt nicht auftreten.

npm start
# → http://127.0.0.1:4200 in normalem Chrome/Edge öffnen
# → DevTools-Konsole: nach "NavigatorLock" filtern
# → wenn keine Errors → Preview-Artefakt, Ignorieren OK
FIX

Falls auch im echten Browser: Lock deaktivieren

In src/app/core/supabase.client.ts die auth-Optionen erweitern:

auth: {
  persistSession: true,
  detectSessionInUrl: true,
  autoRefreshToken: true,
  storageKey: 'sc.auth',
  flowType: 'pkce',
  lock: () => Promise.resolve() // disable Navigator Lock
}
Trade-off: ohne Lock können konkurrierende Tabs theoretisch gleichzeitig refreshen — bei PKCE mit single-flight Token-Server eher unkritisch.

§ 3<html lang> bleibt "en" bei DE-UI

document.documentElement.lang ist "en" während die UI auf Deutsch läuft. ngx-translate setzt das HTML-Lang-Attribut nicht automatisch. SEO + Screenreader-relevant (besonders für Verse-News mit deutschen Titles).

FIX

Sync in AppComponent

In src/app/app.component.ts Konstruktor:

constructor() {
  const t = inject(TranslateService);
  // Initial set
  document.documentElement.lang = t.currentLang ?? t.fallbackLang ?? 'de';
  // Sync auf Sprachwechsel
  t.onLangChange.subscribe(e => {
    document.documentElement.lang = e.lang;
  });
}
Bonus: Wenn du bereits fallbackLang (§1) durchziehst, kannst du beide Fixes im selben Commit landen.
